## 1. What it is

Multi-tenant, AI-powered study app for the US market. Generates personalized
questions + flashcards from admin-uploaded study materials, adapting to each
student's knowledge state. Two segments: **families** (parent+child) and
**schools** (teacher+students). Flutter app (single codebase, admin + student
flavors), Python/FastAPI backend, Azure everything.

Read `knowledge.md` first — it's the canonical architecture/schema/design doc.
`CLAUDE.md` has the builder ethos (Boil the Lake, Search Before Building,
Anti-Slop, Confusion Protocol) and is enforced, not aspirational.

## 7. Non-obvious gotchas (these have bitten us)

- **Deploy tag trap (FIXED `e30010f`, but know it)**: container-app updates must
  use the unique commit-SHA image tag, NOT `:latest`. Updating to the same image
  *string* leaves the revision template unchanged → Azure rolls no new revision →
  stale code keeps running even though `:latest` points at a new digest. If a
  deploy "succeeds" but behavior doesn't change, check the active revision's image
  tag: `az containerapp revision list -g rg-ssa2-dev -n ca-api-dev`.
- **In-memory test fakes hid ~10 real bugs** that only surfaced on the first
  real-Azure run (deploy/config drift, missing deps, Cosmos sort policy, OpenAI
  quota gating, SDK renames). Tests passing ≠ works on Azure. Smoke-test against
  real services for pipeline changes (`backend/scripts/smoke_test_*.py`).
- **Cosmos**: one DB per tenant (`tenant_{id}`), always pass partition key,
  `replace_one` not `update_one`, soft-delete only (`deleted_at`), IDs prefixed
  (`usr_`,`wsp_`,`doc_`,`qst_`,`ntk_`,…). New collections (`notification_tokens`,
  `notification_dispatches`, `gamification`) auto-create on first write.
- **Document Intelligence**: PDF works with `prebuilt-read`; DOCX does NOT.
- **AI Search**: `VectorizedQuery` uses `k` not `k_nearest_neighbors` in the
  pinned SDK (was a rename bug).
- **Model schema changes were all additive/optional** — no DB migrations needed;
  old prefetched questions read fine under new Pydantic models.
